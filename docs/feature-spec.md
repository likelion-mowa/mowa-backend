# MVP 기능 명세서

## 1. 문서 목적 및 범위

> **목적**: PRD에서 확정한 문제·사용자 니즈·서비스 목표와 P0 MVP 기능을 실제 개발 및 QA가 가능한 수준으로 구체화한다.
> 

본 명세는 새로운 기능 아이디어를 추가하지 않고, 아래 핵심 흐름을 구현하기 위한 기능·입력·출력·정책·예외·시나리오를 정의한다.

> **걷기 활동 자동 감지 → 걷기 종료 추정 → 기록 제안 푸시 → 사진 및 최소 경험 입력 → AI 산책 경험 재구성 → 사용자 확인·수정 → 경험 카드 저장 → 아카이브에서 다시 조회**
> 

### 핵심 가치

- **자연스러운 포착**: 사용자가 산책의 시작·종료를 직접 선언하지 않아도 기록 계기를 제공한다.
- **최소한의 개입**: 산책 중 현재 경험을 유지하고 기록 행동은 짧게 만든다.
- **경험의 맥락화**: 사진·시간·장소·사람·감정·상황의 단서를 하나의 경험으로 연결한다.
- **회상 가능한 보존**: 시간이 지난 뒤 당시 사람·감정·상황을 이해할 수 있는 경험 단위로 저장한다.

# R1. 산책 경험 자동 포착 및 기록

## Requirement 정의

사용자가 자신의 활동을 먼저 산책으로 인식하거나 시작·종료 버튼을 조작하지 않아도, 스마트폰의 걷기 활동을 기반으로 산책 기록 후보를 포착하고 적절한 기록 계기를 제공한다. 기록 진입 후에는 현재 경험을 방해하지 않도록 최소한의 사용자 입력만 요구한다.

### 완료 조건

- 사용자가 별도의 산책 시작 조작을 하지 않아도 걷기 활동을 산책 기록 후보로 탐지할 수 있다.
- 사용자는 시스템이 제안한 후보를 `남기기 / 건너뛰기`로 직접 확정할 수 있다.
- 사진 없이도 기록 흐름을 계속 진행할 수 있다.
- 주관적 맥락 입력은 원탭 선택 중심이며 필수 텍스트 입력을 요구하지 않는다.

# F1. 걷기 활동 자동 감지 및 기록 트리거

## 기능 정의

스마트폰의 활동 정보를 기반으로 일정 시간 이상 지속된 걷기 활동을 감지하여 **산책 기록 후보**를 생성하고, 걷기 종료 또는 비활동 전환이 추정되는 시점에 푸시 알림으로 기록을 제안한다.

### 사용 주체

- 서비스 사용자
- 백그라운드에서 걷기 활동을 감지하는 시스템

### 선행조건

- 사용자가 활동 감지에 필요한 OS 권한을 허용한 상태여야 한다.
- 푸시 알림을 받으려면 알림 권한이 허용되어야 한다.
- 위치 기반 맥락을 수집하려면 위치 권한이 필요하다.

### 입력 데이터

| 입력 | 출처 | 용도 |
| --- | --- | --- |
| 걷기 활동 상태 | 스마트폰 활동/모션 정보 | 걷기 지속 여부 판단 |
| 활동 시작·변화 시각 | 기기 시스템 | 후보 시작·종료 추정 |
| 위치 변화 | 위치 정보 | 실제 이동 여부 및 장소 맥락 보조 |
| 차량·대중교통 이동 상태 | 활동 상태 정보 | 산책 후보 제외 판단 보조 |

### 시스템 동작

1. 백그라운드에서 걷기 활동이 감지된다.
2. 걷기가 일정 조건 이상 지속되면 `산책 기록 후보`를 생성한다.
3. 차량·대중교통 이동으로 판단되는 구간은 산책 후보에서 제외하는 방향으로 처리한다.
4. 걷기 종료 또는 비활동 전환이 추정되면 사용자에게 기록 제안 푸시를 제공한다.
5. 사용자가 `남기기`를 선택하면 F2 최소 경험 기록으로 이동한다.
6. 사용자가 `건너뛰기`를 선택하면 해당 후보는 산책 경험으로 저장하지 않는다.

### 출력 데이터

- 산책 기록 후보 ID
- 걷기 시작 추정 시각
- 걷기 종료 추정 시각
- 걷기 지속 시간
- 위치/주요 장소 정보(권한 및 수집 가능 시)
- 이동 경로 정보(정책상 수집하는 경우)
- 후보 상태: `제안 전 / 제안됨 / 기록 진행 / 건너뜀`
- 사용자에게 노출되는 기록 제안 푸시

### 화면 표시 및 피드백

푸시 예시:

> **방금 걸었던 시간을 산책으로 남길까요?**
> 

사용자 선택:

- `남기기`
- `건너뛰기`

### 정책

- 시스템은 감지한 걷기를 사용자의 실제 의도와 무관하게 산책으로 자동 확정하지 않는다.
- 산책 후보는 사용자가 `남기기`를 선택한 경우에만 기록 흐름으로 전환한다.
- 사용자가 직접 산책 시작·종료 버튼을 누르는 것을 기본 흐름으로 요구하지 않는다.
- 차량·대중교통 이동은 산책 후보에서 제외하는 방향으로 설계한다.
- 자동 감지 기능은 사용자가 권한 및 설정을 통해 제어할 수 있어야 한다.

### 예외/실패 상황

- **활동 감지 권한 없음**: 자동 걷기 감지를 수행할 수 없으며 권한 필요 상태를 안내한다. 권한 거부 후 재안내 방식은 결정 필요.
- **알림 권한 없음**: 백그라운드 푸시를 통한 기록 제안을 제공할 수 없다. 대체 기록 진입 방식 제공 여부는 결정 필요.
- **위치 권한 없음**: 위치·장소·경로 기반 데이터 수집이 제한된다. 위치 없이 기록 흐름을 허용할지 정책 결정 필요.
- **산책 오탐지**: 사용자는 `건너뛰기`를 선택해 산책 경험으로 저장하지 않을 수 있다.
- **차량/대중교통과 걷기가 혼합됨**: 어떤 구간을 산책 후보에 포함할지 세부 정책 결정 필요.
- **짧은 걷기/정지 반복**: 하나의 후보로 묶는 기준은 결정 필요.

### 시나리오

> 사용자가 친구와 시간을 보내고 집으로 걸어간다. 사용자는 별도로 산책을 시작하지 않았지만 시스템이 일정 시간의 걷기를 감지한다. 이후 사용자가 집에 도착해 비활동 상태로 전환되면 시스템이 걷기 종료를 추정하고 `방금 걸었던 시간을 산책으로 남길까요?` 푸시를 제공한다. 사용자가 `남기기`를 선택하면 최소 경험 기록 화면으로 이동한다.
> 

### Spec

#### S1-1. 산책 기록 후보 생성

- **입력**: 걷기 상태, 지속 시간, 활동 상태 변화, 위치 변화(가능 시)
- **출력**: 산책 기록 후보 및 추정 시작 시각
- **정책**: 후보는 산책 확정 데이터가 아니며 사용자 확인 전까지 임시 상태로 유지한다.
- **예외**: 활동 감지 권한이 없거나 시스템 정보가 불충분하면 자동 후보 생성을 수행할 수 없다.

#### S1-2. 종료 추정 및 기록 제안

- **입력**: 걷기 종료/비활동 전환 상태, 산책 기록 후보
- **출력**: 기록 제안 푸시, 사용자 선택 결과
- **정책**: `남기기` 선택 시 기록 단계로 이동하고, `건너뛰기` 선택 시 경험 카드가 생성되지 않는다.
- **예외**: 알림 권한이 없을 때의 대체 UX는 결정 필요.

### 결정 필요 질문

1. 산책 후보로 판단하는 **최소 연속 걷기 시간**은 얼마인가?
2. 걷기 종료를 판단하는 **비활동 지속 시간**은 얼마인가?
3. 하루 동안 기록 제안 푸시를 제공할 **최대 횟수 및 최소 간격**은 얼마인가?
4. 활동/위치 권한 거부 시 재요청 시점과 안내 방식은 어떻게 할 것인가?
5. 걷기와 차량 이동이 혼재할 경우 산책 구간을 어떤 기준으로 분리할 것인가?

# F2. 사진 중심 최소 경험 기록

## 기능 정의

사용자가 기록 제안을 수락하면 사진 한 장과 최소한의 주관적 정보만으로 산책 경험의 단서를 남긴다. 날짜·시간·장소·걷기 시간 등 기기에서 확보 가능한 객관적 정보는 자동 연결하고, AI가 임의로 판단하면 안 되는 동반자·감정·상황은 사용자가 직접 선택한다.

### 사용 주체

- 산책 기록 후보에서 `남기기`를 선택한 사용자

### 선행조건

- F1에서 산책 기록 후보가 생성되고 사용자가 기록 진행을 선택한 상태이다.
- 사진 촬영 시 카메라 권한이 필요하다.
- 기존 사진 선택 기능을 제공하는 경우 사진 라이브러리 권한 정책은 별도 결정이 필요하다.

### 입력 데이터

| 입력 | 필수 여부 | 수집 방식 |
| --- | --- | --- |
| 대표 사진 | 선택 | 카메라 촬영 또는 사진 없이 진행 |
| 동반자 | 선택 | 혼자 / 친구 / 연인 / 가족 / 반려동물 등 원탭 선택 |
| 산책 후 감정 | 선택 | 원탭 선택 |
| 산책 상황/계기 | 선택 | 기분 전환 / 생각 정리 / 대화 / 이동 / 운동·소화 등 원탭 선택 |
| 한마디 | 선택 | 짧은 텍스트 또는 추후 정책에 따라 음성 입력 |
| 날짜·시간·걷기 시간 | 자동 | F1 산책 후보 데이터 |
| 장소·경로 | 자동/선택 | 위치 권한 및 수집 정책에 따라 연결 |

### 시스템 동작

1. 사용자가 `남기기`를 선택하면 간단한 기록 화면으로 진입한다.
2. 사진 촬영을 우선 제공하되 사진 없이도 다음 단계로 진행할 수 있다.
3. 기기에서 확보 가능한 객관적 정보를 자동 연결한다.
4. AI가 임의로 판단하면 안 되는 주관적 맥락을 원탭 선택 방식으로 입력받는다.
5. 사용자는 일부 질문을 건너뛸 수 있다.
6. 입력 완료 후 F3 AI 산책 경험 재구성으로 전달한다.

### 출력 데이터

- 기록 초안 ID
- 대표 사진 파일/참조 정보(선택)
- 동반자 값(선택)
- 감정 값(선택)
- 산책 상황 값(선택)
- 사용자 한마디(선택)
- 자동 연결된 날짜·시간·장소·걷기 시간·경로 정보

### 화면 표시 및 피드백

- 한 화면에서 과도한 입력을 요구하지 않는다.
- 원탭 선택을 우선한다.
- 필수 텍스트 입력은 두지 않는다.
- 사진을 촬영하지 않아도 다음 단계로 이동할 수 있음을 명확히 표시한다.
- 건너뛸 수 있는 질문은 `건너뛰기` 상태를 제공한다.

### 정책

- 사진은 기본 기록 수단이지만 필수값이 아니다.
- 감정·관계 등 주관적 정보는 AI가 사진만 보고 임의로 확정하지 않는다.
- 사용자 입력이 없는 항목은 `알 수 없음` 또는 미입력 상태로 유지하고 AI가 내용을 만들어 채우지 않는다.
- 객관적 정보는 가능한 범위에서 자동 연결하여 사용자의 직접 입력을 최소화한다.
- 텍스트 입력은 선택 사항으로 둔다.

### 예외/실패 상황

- **카메라 권한 없음**: 사진 없이 기록 진행은 가능하다. 카메라 권한 재요청 UX는 결정 필요.
- **사진 촬영 취소**: 사진 없이 다음 단계로 진행할 수 있다.
- **위치 데이터 없음**: 장소 없이 기록을 생성할 수 있는지 최종 정책 결정 필요.
- **일부 질문 미응답**: 응답한 정보만 AI 입력 데이터로 전달하며 미응답 정보를 AI가 추측하지 않는다.
- **네트워크 없음**: 사용자 입력 자체는 가능하나 AI 생성 요청은 수행할 수 없다. 초안을 로컬에 임시 저장할지 여부는 결정 필요.

### 시나리오

> 사용자가 기록 제안 푸시에서 `남기기`를 선택한다. 카메라 화면에서 현재 장면 사진 한 장을 촬영하고, `친구`, `편안함`, `대화하며 걷기`를 원탭으로 선택한다. 별도의 문장은 작성하지 않고 완료한다. 시스템은 걷기 후보에서 확보한 날짜·시간·장소·걷기 시간을 함께 묶어 AI 생성 입력 데이터로 전달한다.
> 

### Spec

#### S2-1. 대표 사진 기록

- **입력**: 카메라 촬영 결과 또는 사진 없음
- **출력**: 대표 사진 참조 정보 또는 미첨부 상태
- **정책**: 사진은 선택이며, 사진이 없다는 이유만으로 기록 생성을 차단하지 않는다.
- **예외**: 카메라 권한 없음, 촬영 취소, 파일 저장 실패 처리 필요.

#### S2-2. 최소 맥락 입력

- **입력**: 동반자·감정·상황·선택적 한마디
- **출력**: AI 생성에 전달할 사용자 맥락 데이터
- **정책**: 미입력 항목은 AI가 추측하지 않는다.
- **예외**: 일부 질문을 건너뛰어도 다음 단계로 이동할 수 있다.

### 결정 필요 질문

1. MVP에서 사진은 **최대 몇 장**까지 허용할 것인가? 현재 기본 UX는 1장이다.
2. 최소 맥락 질문을 항상 동일하게 제공할지, 상황에 따라 일부만 제공할지 결정이 필요하다.
3. `한마디` 입력에 음성을 P0에 포함할지 텍스트만 제공할지 결정이 필요하다.
4. 위치 정보가 없을 때 장소 없는 기록 생성을 허용할지 결정이 필요하다.
5. 네트워크가 없을 때 기록 초안을 로컬에 임시 보관할지 결정이 필요하다.

# R2. 산책 경험 맥락 재구성

## Requirement 정의

사용자가 직접 긴 일기를 작성하지 않아도, 자동 수집한 객관적 단서와 사용자가 선택한 주관적 단서를 AI가 하나의 산책 경험으로 구조화한다. AI 생성 결과는 사용자가 최종 확인·수정한 후에만 확정 기록으로 저장한다.

### 완료 조건

- AI는 입력된 정보 범위에서 제목·일기·태그를 생성할 수 있다.
- 입력되지 않은 감정·관계·대화·사건을 새로 만들어내지 않는다.
- 사용자는 AI 결과를 저장 전에 확인·수정할 수 있다.
- 사용자가 저장하지 않으면 아카이브에 확정 경험이 생성되지 않는다.

# F3. AI 산책 경험 재구성 및 일기 생성

## 기능 정의

사진, 날짜·시간·장소·걷기 정보와 사용자가 입력한 동반자·감정·상황 등의 단서를 AI가 연결하여 짧은 산책 경험 초안을 생성한다. AI의 역할은 기억을 창작하는 것이 아니라 이미 확보된 단서를 회상하기 쉬운 형태로 구조화하는 것이다.

### 사용 주체

- 최소 경험 입력을 완료한 사용자
- 산책 경험 초안을 생성하는 AI 시스템

### 선행조건

- F2의 기록 초안이 존재해야 한다.
- AI 생성에 필요한 서버/네트워크 연결이 가능해야 한다.

### 입력 데이터

- 대표 사진(선택)
- 날짜·시간
- 주요 장소(확보 시)
- 걷기 지속 시간
- 이동 경로(확보 및 정책상 사용하는 경우)
- 동반자(사용자 입력 시)
- 감정(사용자 입력 시)
- 산책 상황/계기(사용자 입력 시)
- 사용자 한마디(입력 시)

### 시스템 동작

1. 기록 초안에서 사용 가능한 입력 데이터를 정리한다.
2. AI에 객관적 단서와 사용자 입력을 전달한다.
3. AI가 제목·짧은 경험 요약/일기·태그를 생성한다.
4. 생성 결과를 F4 사용자 확인 화면에 전달한다.

### 출력 데이터

- 산책 경험 제목
- 짧은 경험 요약 또는 2~4문장 수준의 산책 일기
- 사람 태그(사용자 입력이 있는 경우)
- 감정 태그(사용자 입력이 있는 경우)
- 장소 태그(객관적 위치 데이터가 있는 경우)
- 상황 태그(사용자 입력이 있는 경우)
- 생성 상태: `생성 중 / 성공 / 실패`

### 정책

- 사용자가 제공하거나 객관적으로 확인 가능한 정보만 생성 근거로 사용한다.
- 입력되지 않은 구체적인 대화 내용을 생성하지 않는다.
- 사진만으로 특정 인물의 신원·관계를 추론하지 않는다.
- 사진만으로 사용자의 감정을 확정하지 않는다.
- 입력되지 않은 사건이나 의미를 사실처럼 생성하지 않는다.
- 태그는 실제 입력 또는 객관적으로 확인된 정보에 대응해야 한다.
- AI 생성 결과는 사용자 확인 전까지 확정 기록이 아니다.

### 예외/실패 상황

- **네트워크 없음**: AI 생성 요청을 수행할 수 없음을 표시한다. 기록 초안 유지 방식은 결정 필요.
- **AI API 실패/타임아웃**: 생성 실패 상태를 표시한다. 자동/수동 재시도 정책은 결정 필요.
- **입력 정보가 적음**: 제공된 정보만으로 짧고 사실 중심의 결과를 생성하며 부족한 정보를 창작하지 않는다.
- **사진 분석 실패**: 사진 정보 없이 나머지 단서만 사용해 생성할지 정책 결정 필요.
- **부적절하거나 민감한 사진/텍스트**: 처리 범위 및 안전 정책은 AI 제공 방식에 맞춰 별도 확정이 필요하다.

### 화면 표시 및 피드백

- 생성 중 로딩 상태를 표시한다.
- 생성 성공 시 제목·본문·태그·대표 사진을 확인 화면으로 제공한다.
- 생성 실패 시 실패 상태와 다음 행동을 안내한다. 재시도 버튼 제공 여부는 결정 필요.

### 시나리오

> 시스템은 `8월 7일 저녁`, `특정 장소`, `38분 걷기`, 사진 1장과 사용자가 선택한 `가족`, `편안함`, `함께 시간 보내기` 정보를 AI에 전달한다. AI는 제공된 정보만 연결해 제목과 짧은 일기를 생성하며, 사용자가 입력하지 않은 대화 내용이나 사건은 추가하지 않는다.
> 

### 결정 필요 질문

1. AI 결과의 기본 본문 길이를 어느 수준으로 제한할 것인가?
2. AI 생성 실패 시 자동 재시도 횟수 또는 사용자 재시도 방식을 어떻게 할 것인가?
3. 사진 분석을 MVP에서 필수 AI 입력으로 사용할지, 단순 대표 이미지로만 활용할지 결정이 필요하다.
4. AI 생성 모델/API 및 민감 정보 처리 정책은 어떤 기준으로 선택할 것인가?

# F4. AI 일기 확인 및 저장

## 기능 정의

AI가 생성한 산책 경험을 사용자가 최종 확인하고 제목·본문·태그·사진을 필요한 범위에서 수정한 뒤 저장하거나, 저장하지 않고 취소할 수 있도록 한다.

### 사용 주체

- AI 산책 경험 초안을 확인하는 사용자

### 선행조건

- F3의 AI 생성 결과가 성공적으로 생성되어야 한다.

### 입력 데이터

- AI 생성 제목
- AI 생성 본문
- 대표 사진
- 사람·감정·장소·상황 태그
- 날짜·시간·걷기 정보
- 사용자 수정 내용
- 사용자 최종 선택: `저장 / 취소`

### 시스템 동작

1. AI 결과를 사용자에게 확정 전 미리보기로 보여준다.
2. 사용자는 제목·본문·태그·사진을 확인한다.
3. 필요한 경우 수정한다.
4. `저장` 선택 시 하나의 산책 경험으로 확정한다.
5. `취소` 선택 시 아카이브에 확정 경험을 생성하지 않는다.

### 출력 데이터

- 확정된 산책 경험 데이터 또는 미저장 결과
- 최종 제목·본문
- 최종 대표 사진
- 최종 사람·감정·장소·상황 태그
- 생성/수정 이력 저장 여부는 정책 결정 필요

### 정책

- AI 생성 결과는 사용자가 저장하기 전까지 사용자의 실제 경험으로 확정하지 않는다.
- 사용자는 AI가 잘못 해석한 제목·본문·태그를 수정할 수 있다.
- 사용자는 사진을 변경하거나 제외할 수 있다.
- `취소`한 결과는 아카이브에 표시하지 않는다.
- AI가 생성한 내용과 사용자 수정 내용의 버전 보존 여부는 결정 필요.

### 예외/실패 상황

- **저장 요청 실패**: 확정 저장 실패를 명확히 표시하고 데이터 유실 방지 방식은 결정 필요.
- **사용자가 저장하지 않음**: 아카이브 기록을 생성하지 않는다. 미저장 초안 보존 여부는 결정 필요.
- **사용자가 모든 AI 본문을 삭제함**: 빈 본문을 허용할지, 최소 제목/메타데이터만 저장할지 결정 필요.
- **사진 제거**: 사진 없는 경험 카드 저장을 허용한다.

### 화면 표시 및 피드백

- AI 생성 결과임을 사용자가 인지할 수 있는 확인 화면을 제공한다.
- `이대로 저장`과 수정 가능한 입력 영역을 제공한다.
- 저장 완료/실패 상태를 사용자에게 명확히 알린다.

### 시나리오

> 사용자가 AI 생성 제목과 일기를 확인한다. 감정 태그는 맞지만 본문의 표현 일부가 마음에 들지 않아 직접 수정한다. `이대로 저장`을 누르면 수정된 내용이 최종 산책 경험으로 저장된다. 사용자가 취소하면 아카이브에는 아무 기록도 생성되지 않는다.
> 

### 결정 필요 질문

1. 저장하지 않은 AI 초안을 임시 보관할 것인가, 즉시 폐기할 것인가?
2. 제목/본문이 비어 있어도 메타데이터 중심 경험으로 저장할 수 있는가?
3. AI 원문과 사용자 수정본의 이력을 별도로 보존할 필요가 있는가?

# F5. 맥락 기반 산책 경험 아카이빙

## 기능 정의

사용자가 확정한 산책 기록을 하나의 `산책 경험` 객체로 저장하고, 목록과 상세 화면을 통해 당시 상황과 맥락을 다시 확인할 수 있도록 한다.

### 사용 주체

- 과거 산책 경험을 다시 확인하거나 수정·삭제하는 사용자

### 선행조건

- F4에서 사용자가 AI 결과를 최종 저장한 경험이 하나 이상 존재해야 한다.

### 입력 데이터

- 경험 ID
- 대표 사진(선택)
- 제목
- AI/사용자 최종 본문
- 날짜·시간
- 주요 장소(있는 경우)
- 동반자(있는 경우)
- 감정(있는 경우)
- 상황/계기(있는 경우)
- 걷기 지속 시간
- 이동 경로(수집 및 저장하는 경우)

### 시스템 동작

1. 저장된 경험을 목록으로 조회한다.
2. 사용자가 특정 경험을 선택하면 상세 정보를 제공한다.
3. 상세 화면에서 사진·제목·본문·태그·객관적 활동 정보를 함께 보여준다.
4. 사용자는 저장된 경험을 수정하거나 삭제할 수 있다.

### 출력 데이터

- 산책 경험 목록
- 산책 경험 상세 데이터
- 수정된 최종 경험 데이터
- 삭제 상태

### 목록 표시 정책

- MVP 기본 조회는 날짜 기준으로 제공한다.
- 카드에는 회상에 필요한 핵심 정보만 노출한다.
- 장소·사람·감정 태그는 해당 데이터가 존재할 때만 표시한다.
- 지도·캘린더·자동 재노출 기능은 P0에서 제외한다.

### 상세 표시 정책

경험 상세에서 다음 정보를 확인할 수 있다.

- 대표 사진
- 산책 경험 제목
- 날짜·시간
- 장소
- 함께한 사람
- 감정
- 상황 또는 산책 계기
- AI/사용자 최종 일기
- 걷기 시간
- 경로(정책상 저장하는 경우)

### 예외/실패 상황

- **저장된 경험 없음**: 빈 아카이브 상태를 제공한다.
- **사진 없음**: 사진 영역 없이 나머지 맥락 정보로 카드를 구성한다.
- **일부 태그 없음**: 없는 정보를 임의로 채우지 않고 해당 항목을 생략한다.
- **목록/상세 조회 실패**: 로딩 실패 상태와 재조회 방식을 제공해야 하며 상세 UX는 결정 필요.
- **삭제**: 삭제 확인 절차와 복구 가능 여부는 결정 필요.
- **수정 저장 실패**: 기존 저장본 유지 여부 및 재시도 정책을 결정해야 한다.

### 시나리오

> 몇 주 뒤 사용자가 아카이브를 연다. 날짜순 목록에서 이전 산책 카드를 선택하면 당시 대표 사진과 함께 누구와 걸었는지, 어떤 감정이었는지, 어디에서 어떤 상황으로 걸었는지와 최종 일기를 한 화면에서 확인한다. 사용자는 시간이 지나도 단편적인 사진이 아니라 당시 맥락이 연결된 하나의 경험으로 산책을 다시 이해할 수 있다.
> 

### Spec

#### S5-1. 경험 목록 및 상세 조회

- **입력**: 사용자 경험 목록 요청, 경험 ID
- **출력**: 경험 카드 목록, 선택 경험 상세 정보
- **정책**: MVP는 날짜 기준의 기본 조회를 우선하고 지도·캘린더·자동 재노출은 제외한다.
- **예외**: 데이터 없음, 조회 실패, 부분 데이터 누락 상태를 처리한다.

#### S5-2. 경험 수정 및 삭제

- **입력**: 수정된 경험 데이터 또는 삭제 요청
- **출력**: 수정 완료 경험 또는 삭제 상태
- **정책**: 사용자는 자신이 확정한 산책 경험의 내용과 태그를 수정·삭제할 수 있다.
- **예외**: 수정/삭제 실패 시 기존 데이터 보존 및 사용자 피드백이 필요하다.

### 결정 필요 질문

1. 경험 카드 목록의 기본 정렬은 최신순으로 확정할 것인가?
2. 삭제는 즉시 영구 삭제할지, 일정 기간 복구 가능한 소프트 삭제로 처리할지 결정이 필요하다.
3. 위치/경로 데이터의 보존 기간과 정밀도는 어떻게 제한할 것인가?
4. 아카이브 데이터의 서버 보관 및 사용자 계정 연동 방식은 어떻게 할 것인가?

# 5. 전체 사용자 시나리오

## 정상 시나리오

> 1. 사용자는 다른 일상 활동의 연장선에서 자연스럽게 걷는다.
> 

> 2. 시스템은 걷기 활동을 자동 감지하여 산책 기록 후보를 생성한다.
> 

> 3. 걷기 종료를 추정한 시점에 `방금 걸었던 시간을 산책으로 남길까요?` 푸시를 제공한다.
> 

> 4. 사용자가 `남기기`를 선택한다.
> 

> 5. 사용자는 사진 한 장을 촬영하거나 사진 없이 진행한다.
> 

> 6. 동반자·감정·상황 등 필요한 정보만 원탭으로 입력하고 나머지는 건너뛸 수 있다.
> 

> 7. 시스템은 날짜·시간·장소·걷기 시간 등 확보 가능한 객관적 정보를 자동 연결한다.
> 

> 8. AI는 사용자 입력과 객관적 단서만 사용해 제목·짧은 일기·태그를 생성한다.
> 

> 9. 사용자는 AI 결과를 확인하고 필요한 부분을 수정한다.
> 

> 10. 사용자가 저장하면 하나의 `산책 경험` 객체로 아카이브에 저장된다.
> 

> 11. 시간이 지난 뒤 사용자는 아카이브에서 사진·사람·감정·장소·상황과 일기를 함께 확인한다.
> 

## 오탐 시나리오

> 1. 시스템이 단순 이동을 산책 후보로 잘못 판단한다.
> 

> 2. 사용자에게 기록 제안이 도착한다.
> 

> 3. 사용자가 `건너뛰기`를 선택한다.
> 

> 4. 해당 후보는 경험 카드로 저장되지 않는다.
> 

## AI 실패 시나리오

> 1. 사용자가 사진과 최소 맥락을 입력한다.
> 

> 2. AI 생성 요청이 실패한다.
> 

> 3. 시스템은 생성 실패 상태를 표시한다.
> 

> 4. 초안 유지·재시도 방식은 최종 정책에 따라 처리한다.
>

# 7. 개발 전 최종 결정 필요 항목

1. **산책 후보 탐지 임계값**: 최소 걷기 시간, 거리, 연속성 기준
2. **종료 판단 기준**: 비활동 지속 시간 및 상태 전환 조건
3. **알림 정책**: 푸시 시점, 일 최대 횟수, 최소 간격, 재알림 여부
4. **권한 정책**: 활동·위치·알림 권한 거부 시 대체 UX
5. **위치/경로 정책**: 수집 여부, 정밀도, 보존 기간
6. **사진 정책**: 최대 장수, 갤러리 선택 허용 여부
7. **최소 입력 정책**: 반드시 받아야 하는 주관적 정보가 있는지 여부
8. **오프라인 정책**: 로컬 초안 저장 및 온라인 복귀 후 AI 재요청 여부
9. **AI 실패 정책**: 재시도 방식, 실패 시 수동 저장 허용 여부
10. **AI 결과 정책**: 본문 길이, 태그 형식, 수정 이력 보존 여부
11. **삭제 정책**: 즉시 삭제/복구 가능한 삭제 방식
12. **계정 및 데이터 저장 정책**: 로그인 필요 여부, 서버 저장 범위, 개인정보 및 위치 데이터 처리 기준
